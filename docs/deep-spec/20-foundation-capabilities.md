# 20. 底层基础能力清单（Foundation Capabilities）

> **定位**：用户原话——"至于一些比较底层的东西，算法模型之类的……例如流式输出这东西不能少，关键词，这种东西要加上去"。本份把 Agent 平台**底层必须做对**的基础能力全部列清：流式输出、结构化输出、文本处理算法、检索算法、并发性能、多模态、前端底层 7 域 ≈65 项。每项 = 是什么 + 怎么做 + 关键参数 + 验收点。
> **对照基准**：OpenAI/Anthropic API 的流式与结构化输出、SSE/WebSocket 工程实践、BM25/向量混合检索实践、生产级并发治理。

## A. 流式输出全家桶（12 项）

| # | 项 | 规格 |
|---|----|------|
| A.1 | SSE 服务端流 | 对话接口必须 SSE（text/event-stream），事件格式：`data: {"type":"delta","content":"..."}` 每行一个 JSON；禁止整段返回后再渲染 |
| A.2 | WebSocket 双向流 | 需要中断/指令注入/多路并行（测试区多路对比）时用 WebSocket；心跳 30s，断线自动重连（指数退避 3 次） |
| A.3 | 事件类型体系 | 统一事件：`start`（开始+元数据）/`delta`（增量文本）/`tool_call`（工具调用中）/`tool_result`（工具结果）/`thinking`（思考过程）/`status`（状态变更）/`error`（错误）/`done`（结束含 token 统计）——前端按类型分别渲染 |
| A.4 | 打字机渲染 | 前端逐 token 渲染：每帧最多渲染 1 个 chunk；SSR 与流式并存时先出骨架后流式填充；长回复自动滚动跟随，用户上翻时暂停跟随 |
| A.5 | 流式中断 | 用户点"停止"→ 发 AbortController/WS close → 后端取消 LLM 请求（provider cancel）→ 已收内容保留可复制 |
| A.6 | 断线恢复 | 流中断后重连并请求 `resume`（服务端缓存最近 200 chunk）；无法恢复时提示"网络中断，已保留部分内容" |
| A.7 | 多路流（对比模式） | 测试区"多模型对比"用 2-4 路并行流，每路独立渲染+延迟标尺；参考 15-ux 高级交互 |
| A.8 | 进度流（任务类） | 长任务（训练/批处理/生成报告）用进度流：`{"type":"progress","stage":"解析文档","percent":45}`；前端进度条+阶段文案 |
| A.9 | 思考过程流 | 支持思考过程（thinking/reasoning）可选展示：默认折叠，点击展开；生产环境可关闭思考流 |
| A.10 | 工具调用流 | 工具调用过程流式呈现：`🔧 正在调用[搜索]...` 实时显示当前工具+参数摘要；多工具按时间线展示 |
| A.11 | 流式兼容 | 所有 LLM provider 适配层统一转成内部 SSE 事件（AgentRuntime.stream 契约）；不支持原生流式的老模型降级为分段伪流（200ms 分片） |
| A.12 | 流式指标 | 首 token 延迟（TTFT）< 1.5s 标定；流式下不统计完整延迟；监控页展示 TTFT 分位（P50/P95） |

## B. 结构化输出与工具调用（10 项）

| # | 项 | 规格 |
|---|----|------|
| B.1 | JSON Mode | 所有支持 provider 开启 JSON mode；输出前附加 schema 约束提示；解析失败自动重试 1 次（修正提示词） |
| B.2 | JSON Schema 约束 | 复杂输出用 JSON Schema（response_format: json_schema）；定义后由后端校验（jsonschema 库），非法则重试并报错信息给模型 |
| B.3 | Function Calling | 工具调用必须走原生 function calling（tool_choice）；无原生支持时降级为"工具描述+JSON 输出解析"双保险 |
| B.4 | 工具 Schema 生成 | 工具定义（name/description/parameters）自动生成：Python 函数签名 + 类型注解 → JSON Schema（pydantic/typing 反射）；description 必须含"何时用/何时不用/示例"（见 17-C） |
| B.5 | 输出校验层 | 模型输出统一过校验管道：类型检查 → 必填字段 → 枚举/正则 → 业务规则；失败返回结构化错误给模型修正，最多 2 次 |
| B.6 | 流式结构化 | 流式+结构化组合：流式输出 JSON 片段，前端边收边解析（增量 JSON 解析器），完成后整体校验 |
| B.7 | 分类/标签输出 | 关键词、标签、意图分类输出规范：限定枚举集合+置信度字段；低置信度（<0.6）标记需人工确认 |
| B.8 | 代码输出 | 代码生成输出带语言标记+fenced block；前端代码高亮+复制+一键运行（沙箱） |
| B.9 | 表格/图表输出 | 结构化数据输出表格（markdown/HTML）；图表数据输出 ECharts option 格式 |
| B.10 | 输出长度控制 | max_tokens 按用途预设（对话 2k/报告 8k/代码 4k）；超长自动分页续写提示 |

## C. 文本处理与算法（12 项）

| # | 项 | 规格 |
|---|----|------|
| C.1 | 分词 | 中文分词：jieba 级即可（默认）；专业领域可挂自定义词典/新词发现 |
| C.2 | 关键词提取 | 算法：TF-IDF 基线 + TextRank 增强 + LLM 精修三层；输出 top-N（默认 5）带权重；供标签生成/搜索联想/摘要（用户点名必做） |
| C.3 | 停用词与清洗 | 通用+领域停用词表；清洗管道：去 HTML/去 emoji（可配置保留）/统一全半角/去除零宽字符（见 17-E 输入预处理） |
| C.4 | 文本归一化 | 简繁转换、大小写、数字单位归一化；用户查询与知识库文本同一管道（保证检索对齐） |
| C.5 | Embedding | 中文模型首选 bge-large-zh / text-embedding-v3；向量维度 1024+；批量嵌入（≤64 条/批）；缓存同文本向量 |
| C.6 | 相似度计算 | 余弦相似度（默认）；支持内积；阈值可配（知识问答 0.7 起，可调） |
| C.7 | 摘要算法 | 提取式（TextRank）兜底 + 生成式（LLM）精修；按长度分级（短/中/长）；流式显示摘要进度 |
| C.8 | 翻译 | 走 LLM 翻译（保持格式/术语表）；术语表可维护（16-B 联动） |
| C.9 | 实体识别 | 规则（正则/词典）+ 模型（LAC/UIE）双层；抽取人名/机构/时间/金额/产品；用于 12-monitor 与结构化入库 |
| C.10 | 意图识别 | 分类模型或 LLM 分类（few-shot 枚举）；意图清单可维护；未知意图走默认兜底（见 17-B 意图衰减） |
| C.11 | 情感/语气分析 | 用于反馈聚合（15-ux 反馈域）：正/负/中性+强度；供 16-J 洞察 |
| C.12 | 文本去重 | MinHash/LSH 近似去重 + 精确指纹（md5）双级；知识库入库与检索结果去重 |

## D. 检索算法（8 项）

| # | 项 | 规格 |
|---|----|------|
| D.1 | BM25 关键词检索 | 关键词侧标配 BM25（ES/Meilisearch 内置或自实现）；中文需分词后索引 |
| D.2 | 向量检索 | HNSW 索引（M=16, efConstruction=200）；top-k 默认 10；带 metadata 过滤（分类/时间/权限） |
| D.3 | 混合检索 | BM25+向量并行 → RRF（倒数排名融合）合并；权重可配（默认 0.5/0.5）；参考 Dify 混合检索（召回精度 +30%） |
| D.4 | 重排（Rerank） | 精排层：bge-reranker 模型对 top-50 重排取 top-10；可开关（默认开，成本敏感可关） |
| D.5 | 查询改写 | 检索前查询改写：同义词扩展/纠错/意图补全（LLM 轻量调用）；改写后与原查询并行检索取并集 |
| D.6 | 检索缓存 | 同查询+同知识库版本缓存结果（TTL 10min，带版本失效）；显著降成本与延迟 |
| D.7 | 检索评估 | 离线：Recall@k/MRR/NDCG 评测集（11-eval 联动）；在线：无答案率/引用点击率（12-monitor） |
| D.8 | 引用溯源 | 检索结果必须带来源（文档 ID+页码/段落）；回答引用可点击回看原文（16-D.6 防幻觉落地） |

## E. 并发、性能与韧性（12 项）

| # | 项 | 规格 |
|---|----|------|
| E.1 | 异步架构 | 请求处理全异步（asyncio/队列）；IO 密集不阻塞；长任务走任务队列（Celery/RQ）+ 状态查询 |
| E.2 | 限流 | 用户级 QPS 限流（令牌桶：默认 5 QPS 可配）+ IP 级 + 全局并发上限；超限返回 429+Retry-After |
| E.3 | 熔断 | 下游（LLM/工具/DB）连续失败（默认 5 次/30s）触发熔断 → 快速失败 + 半开恢复探测；配置见 17-I.2 |
| E.4 | 重试策略 | 幂等请求自动重试：指数退避（1s/2s/4s，3 次）+ 抖动；仅对 5xx/超时/429 重试；写操作必须幂等键（17-C.1） |
| E.5 | 超时体系 | 分层超时：LLM 首 token 10s/总时长 120s、工具 30s、检索 3s、HTTP 入口 5s；超时默认返回部分结果而非报错 |
| E.6 | 缓存分层 | L1 内存（进程内，TTL 30s）+ L2 Redis（TTL 按场景）；缓存键含版本号；主动失效（写后清） |
| E.7 | 批处理 | 嵌入/检索/日志上报批量聚合（≤64/批）；批量窗口 100ms |
| E.8 | 连接池 | DB/Redis/HTTP 连接池复用；空闲超时回收；监控池水位 |
| E.9 | 背压与队列 | 突发流量入队列削峰（工作队列长度告警阈值）；拒绝策略：降级直答（无工具）而非排队无限等 |
| E.10 | 资源隔离 | 高优请求（实时对话）与低优任务（批处理/训练）分队列；GPU/API 配额隔离（16-F 联动） |
| E.11 | 优雅降级 | 主模型不可用 → 备用模型 → 规则兜底（FAQ 匹配）；检索不可用 → 直答（提示无知识库）；每个降级路径有日志与告警 |
| E.12 | 性能基准 | 对话 P95 < 3s（含首 token 1.5s）、检索 P95 < 500ms、管理 API P95 < 300ms；压测 k6 回归（17-K.7） |

## 底层能力验收清单（发布前逐项验证）

1. 对话是否真流式（首 token 前有骨架，逐字渲染，可中断）？
2. 结构化输出是否 100% 通过 schema 校验（非法自动修正）？
3. 关键词提取是否在知识库/搜索/标签三处可用？
4. 检索是否有混合+重排+引用溯源？
5. 限流/熔断/重试/超时四件套是否在生产配置生效？
6. P95 是否达标（对话 3s/检索 500ms）？
7. 降级路径是否可手动演练？
