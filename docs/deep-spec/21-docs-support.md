# 21. 文档与辅助体系（Docs & Error Support）

> **定位**：用户原话——"还有报错指令，报错文档，使用文档等等比较细节，辅助人去使用的东西也要有"。本份定义**辅助人使用产品的全部文档与报错机制**：错误码体系、前端报错提示、报错文档、使用文档、开发者文档、管理员文档、文档工程 7 域 ≈55 项。
> **核心思想**：①任何报错 = 三层信息（用户能懂的话 + 错误码 + 排查文档链接）；②任何功能 = 三步文档（怎么用 + 出错怎么办 + 原理是什么）；③文档是产品功能不是附属品，缺失文档 = 功能未完成。

## A. 错误码体系（9 项）

| # | 项 | 规格 |
|---|----|------|
| A.1 | 错误码结构 | `{段位}{模块}{序号}`：如 `E-LLM-1001`（E=错误类型段，LLM=模块，1001=序号）；HTTP 状态码与业务错误码一一对应（4xx/5xx） |
| A.2 | 段位规范 | E=错误（Error）、W=警告（Warning）、I=信息（Info）；错误段细分：`AUTH` 鉴权 / `PERM` 权限 / `VALID` 参数校验 / `LLM` 模型 / `TOOL` 工具 / `RAG` 检索 / `TASK` 任务 / `SYS` 系统 / `NET` 网络 |
| A.3 | 错误码表 | 全局错误码表文档（docs/error-codes.md）：错误码 / 消息模板 / HTTP 状态 / 触发条件 / 排查指引 / 文档链接；新错误码必须登记，禁止裸 return 字符串 |
| A.4 | 错误消息模板 | 三段式：**用户话**（做了什么失败，怎么办）+"错误码 XXXX"+"[查看排查指南](链接)"；例："保存失败，模型配置未通过校验。错误码 VALID-2003，查看排查指南" |
| A.5 | 内部错误隔离 | 用户可见消息不含堆栈/内部路径/密钥（17-H.3）；完整堆栈进日志（脱敏后，见 17-K.4）；生产环境 debug 详情需权限 |
| A.6 | 错误码版本化 | 错误码一旦发布不删除只废弃（deprecated 标记）；文档标注引入版本 |
| A.7 | 错误码国际化 | 错误消息模板支持多语言（i18n 键：`error.E_LLM_1001.message`）；错误码本身不翻译 |
| A.8 | 错误聚合 | 监控侧按错误码聚合统计（Top 错误/错误率趋势）；新错误码首次出现触发告警（12-monitor 联动） |
| A.9 | 错误码自检 | 发版前脚本校验：错误码唯一、均有文档、均有模板、均有处理分支（CI 卡点） |

## B. 前端报错指令（8 项）

| # | 项 | 规格 |
|---|----|------|
| B.1 | 提示分级 | 致命（弹窗/整页错误页）/ 严重（红色横幅+阻断）/ 警告（黄色 toast 可忽略）/ 提示（蓝色信息）；分级不滥用，80% 场景用 toast 级 |
| B.2 | Toast 规范 | 右上角出现，3-5s 自动消失；内容=问题+动作（"保存失败，请重试"）；支持手动关闭；同错误 30s 内不重复弹 |
| B.3 | 内联错误 | 表单校验错误在字段下方内联显示（红字+图标）；提交失败在表单顶部横幅汇总 |
| B.4 | 空态/异常态 | 加载失败显示重试按钮（"加载失败，点击重试"）；500 错误显示友好错误页（错误码+重试+返回）而非白屏 |
| B.5 | 错误恢复引导 | 常见错误提供一键动作："模型连接失败 → [重新测试连接] / [查看配置] / [查看指南]"；AI 对话错误提供"重试/换模型/精简输入"三选项 |
| B.6 | 流式错误内联 | 流式对话中断：消息内联显示"网络中断"+保留已收内容+"继续生成"按钮（20-A.6 联动） |
| B.7 | 报错即上报 | 前端错误自动上报（Sentry/自建，H.6）+ 用户可选"提交反馈"附上下文；错误事件含错误码与操作步骤 |
| B.8 | 报错可复现 | 错误弹窗含"复制错误信息"按钮（含错误码+时间+操作路径），便于用户贴给支持人员 |

## G. 文档工程（6 项）

| # | 项 | 规格 |
|---|----|------|
| G.1 | 文档即代码 | 文档与代码同仓（docs/）；Markdown+Git 版本化；PR 评审包含文档变更 |
| G.2 | 文档站点 | 自动构建文档站（MkDocs/VitePress）：目录/搜索/版本切换/暗色模式；部署与产品同域子路径 |
| G.3 | 自动生成 | API 文档从代码生成（OpenAPI）；数据字典从模型生成；配置参考从 schema 生成——杜绝手写漂移 |
| G.4 | 文档质量门禁 | CI：链接检查（404 检测）/代码块可执行性/必读文档存在性（README/快速开始/错误码表）缺失即失败 |
| G.5 | 文档反馈 | 每页"此文档是否有帮助"（是/否+反馈框）；低分页进入优化队列；文档更新随版本发布 |
| G.6 | 多语言与版本 | 文档版本跟随产品版本（v0.x 文档可切换）；翻译流程（中→英）；截图随版本更新 |

## 文档完备性自检（发版前 10 问）

1. 每个新错误码是否登记到错误码表并有排查手册条目（A.2/C.1）？
2. 每个用户可见报错是否"人话+错误码+文档链接"三件套齐全（A.4）？
3. 每个新模块是否有用户手册章节+快速开始覆盖（D.1/D.2）？
4. 每个新 API 是否自动生成文档且可在线调试（E.2）？
5. 部署/升级步骤是否可照着完成并含回滚（E.5）？
6. FAQ 与已知问题是否同步更新（C.2/C.3）？
7. 文档站构建与链接检查是否通过（G.2/G.4）？
8. 管理员手册是否覆盖新增管理功能（F.1）？
9. 帮助中心搜索能否命中新功能（D.5）？
10. 视频/截图是否与当前版本一致（D.4/G.6）？
