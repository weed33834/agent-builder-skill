# 深度规格统一模板（Deep Spec Template）

> 本目录（docs/deep-spec/）用于承载**模块级深度规格**，与 feature-checklist.md（广度清单）和 full-spec.md（页面级规格）互为补充。
> 分工：checklist 回答"有没有"；full-spec 回答"界面上长什么样"；**deep-spec 回答"到底怎么做、怎么配、怎么管、怎么跑"**。

## 为什么需要这一层

用户发现大量 Agent 项目的通病是**空壳**：界面有按钮、后端有路由、文档有一行描述，但功能既不真正嵌入运行时链路，配置也说不清。本模板强制每个模块按 7 个维度写深写全，缺一不可。

## 每个模块必须包含的 7 个章节

### 1. 定位与总体架构
- 这个模块解决什么问题（业务价值）
- 它在整个系统中的位置（数据流图：谁产生、谁消费、谁存储）
- 与相邻模块的边界（如：提示词 vs 上下文 vs 记忆，如何分工）

### 2. 资产模型（数据模型全字段）
- 本模块管理的"资产"是什么（prompt/sandbox 环境/上下文策略…）
- 每个字段：名称 | 类型 | 必填 | 默认值 | 说明 | 取值/约束
- 资产的生命周期：创建 → 草稿 → 发布 → 使用 → 归档 → 删除

### 3. 配置项全清单（怎么配置）
- 每个配置项：键名 | 类型 | 默认值 | 说明 | 取值范围 | 生效时机（重启/热加载/按请求）
- 配置存放位置：agent.yaml / .env / 数据库 / 管理界面
- 配置校验与错误提示

### 4. 管理界面（增删改调 + 辅助功能）
- 列表页：筛选/搜索/排序/批量操作
- 编辑器：字段、校验、实时反馈
- 辅助功能：AI 自动生成 / 导入（文件/URL/市场/Git/跨平台）/ 模板 / 版本 diff / 回滚 / A-B 测试 / 复制 / 导出
- 每个操作必须对应到：前端组件 + 后端接口

### 5. 运行时嵌入（真正被调用，不是摆设）
- 完整调用链：用户在对话中触发 → 请求进入 → 本模块资产如何被加载、渲染、注入 → 结果如何回流
- 关键：**给出真实代码路径**（模块/函数/行），确保可验证
- 触发条件、缓存策略、失败降级

### 6. 安全与权限
- 谁能看/谁能改/谁能删（角色矩阵）
- 审计日志记录点
- 敏感信息处理（密钥、Prompt 内容、用户数据）

### 7. 前后端对齐矩阵 + 状态 + 缺口
- 表格：功能 | 后端接口 | 前端组件 | 状态(✅/🔶/⬜) | 缺口说明
- 缺口要给出补齐路径（哪个文件、什么接口）

## 写作规范（用户明确要求）

1. **不写空壳**：写"有管理界面"必须落到"哪个组件哪个接口哪个函数"；写"支持导入"必须列全导入通道和格式。
2. **不省篇幅**：每个配置项单独一行，宁可多写不可漏写。
3. **可验证**：每章末尾留"验证方法"（怎么手工/脚本验证该功能真实工作）。
4. **追求完全性**：对照豆包/GPT/Coze/Dify/LangSmith 等同类产品功能，逐条吸收。
