## A. 对话风格与"AI 味"（死板风格的 12 种病）

| # | 坑 | 现象（用户感受） | 根因 | 避免方法 | 检测方法 |
|---|-----|------------------|------|----------|----------|
| A.1 | 模板化开场 | 每条回复都"好的！"开头，像客服机器人 | 系统提示词写死礼貌模板 | 风格随机化：多套开场轮换；仅必要时开场 | 开场白去重统计（同一开场 >30% 即告警） |
| A.2 | 过度道歉 | "非常抱歉给您带来不便"×N，占用篇幅 | 安全调教过度，把道歉当保险 | 禁止无过错道歉；真出错时一次道歉+解决方案 | 正则统计道歉词密度 |
| A.3 | 废话堆砌 | "可能/建议/通常"堆一段，无操作指引 | 模型规避风险的本能 | 要求"有效推进三要素"：明确动作/可验证信息/下一步 | 回复必须含动作指令或具体信息点，否则人工复核标记 |
| A.4 | 展示知识储备 | 用户问 A，先写 500 字背景再回答 | 模型默认模式=展示所学 | 约束"先答后展"：直接回答→按需补充 | 首段是否直接命中问题（embedding 相似度） |
| A.5 | 列表轰炸 | 什么都是 1.2.3.4，连"今天天气"也列点 | 提示词里"结构化输出"滥用 | 按内容类型给格式：短答不列表；长答才分节 | 短回复（<100 字）含 3+ 列表项即标记 |
| A.6 | 冷冰冰机械感 | 无语气词、无情感，像说明书 | 提示词要求"专业严谨"过度 | 注入人格锚点+语气示例（few-shot） | 语气分类模型抽检 |
| A.7 | 每答必带免责声明 | "作为 AI 模型，我……"每轮重复 | 安全提示词残留 | 仅涉敏话题才声明，且一句带过 | 免责声明频率统计 |
| A.8 | 复读机式确认 | "您的意思是……吗？"每轮都反问 | 确认机制无阈值 | 明确时才确认；多数情况直接执行+给结果 | 反问句占比监控 |
| A.9 | 过度承诺 | "绝对没问题！"然后做不到 | 讨好型倾向 | 承诺前先验证能力边界；做不到明说 | 承诺→结果一致性抽查 |
| A.10 | 回避直接回答 | 绕圈子、不表态，尤其"好不好/能不能" | 政治正确调教过度 | 明确"该表态就表态，可给概率+理由" | 无结论回复占比（回复无任何判断词） |
| A.11 | 长度失控 | 该短的长篇大论，该长的三句话带过 | 无长度指令约束 | 按场景给长度预算（如 ≤150 字/≤800 字） | 长度与类型预期偏差检测 |
| A.12 | 回复同质化 | 换模型/换人设，味道一样 | 风格指令没进系统提示词 | 风格参数化（语气/长度/称呼/emoji 密度可配） | A/B 对比不同风格配置的用户反馈 |

## B. Agent 决策与推理错误（AI 在 Agent 上最常犯的 12 种错）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| B.1 | 死循环 | Agent 反复调用同一工具不收敛，token 烧光 | 循环无最大步数/无退出条件 | 强制 max_iterations + 步数预算 + 循环检测（重复工具+参数即终止） | trace 里同工具调用 ≥3 次同参即告警 |
| B.2 | 工具选择错误 | 有计算器却用搜索算 1+1 | 工具描述不清晰/无场景示例 | 工具描述写"何时用/何时不用"+few-shot 示例 | 工具选择混淆矩阵统计 |
| B.3 | 幻觉调用 | 调用不存在的参数/端点，编造 ID | 对真实 API 无验证 | 工具参数 schema 强校验（JSON Schema）+ 引用检查 | 参数校验失败率监控 |
| B.4 | 过度自信 | 结果没验证就说"已完成" | 无验证环节 | 关键任务强制"执行→验证→报告"三步 | 无验证即报成功的 trace 标记 |
| B.5 | 过早放弃 | 一次失败就报错结束 | 无重试策略 | 分类重试（网络/临时错重试，业务错停止）+退避 | 首次失败即终止的任务占比 |
| B.6 | 温度失控 | 相同输入不同输出，生产行为不可复现 | temperature 未固定 | 生产环境 temperature ≤ 0.3（黄金标准）；高随机仅限创意场景 | 同输入输出 diff 监控 |
| B.7 | 并行调用冲突 | 两个工具同时写同一资源互相覆盖 | 无并发控制 | 写操作串行化/加锁；读可并行 | 写冲突错误计数 |
| B.8 | 错误传播 | 中间一步失败，后续拿着错误数据继续算 | 无检查点/无数据校验 | 每步输出 schema 校验，不合格即熔断（管道+熔断模式） | 错误数据继续传播的 trace 检测 |
| B.9 | 上下文污染 | 上个任务的残留影响下个任务 | 会话/任务上下文未隔离 | 任务级上下文隔离，完成即清理 | 跨任务引用检测 |
| B.10 | 指令漂移 | 会话中期开始不遵守初始指令 | 长上下文稀释 | 关键指令周期性重申/锚点重注入 | 指令遵循度评估抽检 |
| B.11 | 走捷径 | 跳过必要步骤直接给结论（奖励黑客） | 目标定义漏洞 | 步骤级验收：每步产物可查，不允许跳步 | 步骤缺失检测 |
| B.12 | 行为漂移 | 今天好好的明天突然抽风（模型更新/数据变化） | 外部依赖变化 | 每日回归测试 + 行为基线对比 + 变化告警 | 回归分数趋势监控（Gartner：年均 54 次失控事件） |

## C. 工具调用坑（生产踩坑 10 条）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| C.1 | 写操作不幂等 | 重试产生重复工单/重复下单 | 无幂等键 | idempotency key（框架注入）+ 写入端去重 | 同 key 重复写检测 |
| C.2 | 重试风暴 | LLM API 超时→SDK 重试→框架重试→网络重传叠加 | 多层重试无上限 | 统一重试策略：单层负责、指数退避、上限次数 | 重试次数分布监控 |
| C.3 | 工具超时不处理 | 工具挂起，Agent 等死 | 无超时/无超时后的分支 | 每工具强制 timeout + 超时分支（重试/跳过/问用户） | 工具超时率监控 |
| C.4 | 返回格式不一致 | 解析失败/字段缺失 | 工具返回无契约 | 工具输出 JSON Schema + 解析容错（缺字段给默认） | 解析失败率 |
| C.5 | 权限过大 | 工具能删库，Agent 一句"清理一下"就执行 | 最小权限缺失 | 工具分级（只读/写/危险），危险操作人工确认（HITL） | 危险工具调用需审批记录 |
| C.6 | 工具描述误导 | 描述含糊，Agent 乱用 | 描述无"何时用/边界" | 描述模板：用途+参数+返回+边界+示例 | 工具调用误用人工抽检 |
| C.7 | 链式误用 | 先查再写顺序错乱/依赖前置未做 | 无依赖描述 | 工具元数据加依赖关系，Agent 引导前置 | 依赖顺序违规检测 |
| C.8 | 工具爆炸 | 工具太多，选择准确率暴跌 | 每加 1 工具故障率上升约 8.7% | 工具分组/按任务动态挂载（只用需要的子集） | 工具总数与误用率相关性 |
| C.9 | 凭据硬编码 | 工具里写死密钥，泄漏即全量暴露 | 快速实现遗留 | 密钥托管（16-L.2），工具只拿引用 | 密钥扫描（git 历史/日志） |
| C.10 | 参数注入 | 用户文本直接拼进工具参数 | 无转义/无白名单 | 参数强校验+按类型强制转换+危险字符拒绝 | 注入样本回归测试 |

## D. 记忆与上下文坑（"金鱼"与"串台" 10 条）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| D.1 | 记忆丢失（金鱼） | 用户刚说不喜欢红色，转头推荐红色 | 短期记忆未归档长期 | 分层记忆+自动沉淀（会话摘要→长期） | 同会话偏好召回测试 |
| D.2 | 记忆串台 | A 用户偏好出现在 B 用户对话 | 记忆无用户隔离 | 记忆键必须含 user_id+scope，检索强制过滤 | 跨用户记忆泄漏测试 |
| D.3 | 上下文爆炸 | 越聊越慢越贵，直至超限 | 无压缩无预算 | token 预算+自动压缩（03-context 压缩策略） | 上下文长度与成本监控 |
| D.4 | 关键信息被压缩掉 | 用户最在意的约束被摘要吞了 | 压缩算法无重要性识别 | 压缩保留"硬约束"（数字/禁止项/承诺） | 压缩前后关键实体召回对比 |
| D.5 | 检索失效 | 明明存了却查不到 | 分块/embedding 策略不当 | 检索质量测试台（16-D.12）+ 同义改写兜底 | 检索命中率监控 |
| D.6 | 记忆过期 | 用三个月前的价格回答今天的问题 | 记忆无时效 | 记忆带时间戳+过期策略（自动失效/提示更新） | 时效性规则检查 |
| D.7 | 敏感记忆泄漏 | 记忆被用于不该用的场景 | 记忆无分级 | 记忆分级（普通/敏感），敏感记忆限制用途 | 敏感记忆使用审计 |
| D.8 | 无遗忘机制 | 用户要求删除的还留着 | 无删除路径 | 记忆删除/遗忘 API+定期清理 | 删除请求合规抽查 |
| D.9 | 多轮意图衰减 | 聊 20 轮后模型忘了最初任务 | 目标信息稀释 | 任务目标锚点重注入（B.10 联动） | 任务目标遵循度 |
| D.10 | 记忆写入竞争 | 并发写记忆互相覆盖 | 无锁 | 写操作串行/版本化 | 写入冲突日志 |

## E. 提示词工程坑（10 条）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| E.1 | Prompt 脆弱性 | 换输入风格就崩（emoji/超长/HTML） | 只按 demo 输入调优 | 输入预处理管道（清洗/截断/危险字符拒绝）+ 熔断 | 对抗样本回归测试（25% 注入/超长/特殊字符） |
| E.2 | 注入攻击面 | 用户文本里"忽略以上指令"生效 | 提示词与不可信输入混放 | 系统指令与用户输入分隔+输入边界标记+注入检测 | 注入样本集定期攻击测试 |
| E.3 | 指令冲突 | 系统提示词互相矛盾，行为随机 | 多来源指令无优先级 | 指令优先级规则（安全>系统>用户>工具），冲突时拒绝 | 指令冲突静态扫描 |
| E.4 | 过度工程 | 5000 字提示词反而更差 | 堆砌而非设计 | 最小化原则：只留必要的；大改小步验证 | 提示词长度-效果相关性分析 |
| E.5 | few-shot 误导 | 示例教坏了模型 | 示例质量差/示例与任务偏离 | 示例要覆盖边界与反例；从真实数据挑选 | 示例有效性评估 |
| E.6 | 角色混乱 | 一个提示词让 AI 同时当客服+法务+销售 | 角色职责未拆分 | 单角色单一职责；复杂任务拆多 Agent | 角色冲突检测 |
| E.7 | 无输出约束 | 要 JSON 给散文，要列表给段落 | 无格式强约束 | 输出格式 Schema+解析校验+重试一次 | 输出格式合规率 |
| E.8 | 版本漂移 | 改了一句提示词，行为全变 | 无版本管理 | 提示词版本化+变更 diff+回滚（01-prompt 版本表） | 变更前后回归对比 |
| E.9 | 依赖模型幻觉 | 提示词里写了不存在的功能，AI 假装做了 | 提示词与代码能力脱节 | 提示词里只提真实存在的工具/接口 | 提示词-能力清单一致性检查 |
| E.10 | 一次性提示词 | 换人维护就废 | 无文档无模板 | 提示词入库+注释+评审+模板化 | 提示词文档覆盖率 |

## F. 数据与知识库坑（9 条）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| F.1 | 脏数据入库 | 垃圾进垃圾出，答案全是噪音 | 无清洗流程 | 入库前清洗（去重/去噪/格式规范）+质量门槛 | 库质量评分（16-D.8） |
| F.2 | 过时数据 | 回答用旧版本政策 | 数据无时效管理 | 数据版本+更新日期+过期标识 | 时效字段检查 |
| F.3 | 格式解析失败 | PDF 表格变乱码，扫描件全丢 | 解析器选型不当 | 按文件类型选解析管线（表格用结构化抽取/扫描件 OCR） | 解析成功率监控 |
| F.4 | 分块破坏语义 | 一句话被切两半，检索答非所问 | 固定大小硬切 | 语义分块+父子块+重叠（16-D.3） | 断句率检测 |
| F.5 | 向量假命中 | 相似度高但语义无关 | embedding 局限 | 混合检索（BM25+向量）+rerank+阈值调优 | 检索相关性人工抽检 |
| F.6 | 知识冲突 | 新旧文档互相矛盾，答案看运气 | 无冲突检测 | 冲突检测任务（同主题不同说法标记）+人工裁决 | 冲突标记数 |
| F.7 | 权限过滤缺失 | 越权文档被检索到 | 检索不过滤 ACL | 检索链路强制 ACL 过滤（16-D.7） | 越权检索测试 |
| F.8 | 引用错误 | 答案引用了不存在/无关的文档 | 引用与生成脱节 | 引用溯源强绑定（生成时锁定引用源，16-D.6） | 引用有效性校验 |
| F.9 | 数据漂移 | 线上数据分布变了，效果悄悄下滑 | 无监测 | 漂移检测（12-monitor）+自动告警 | 漂移指标监控 |

## G. 评测与验收坑（8 条）

| # | 坑 | 现象 | 根因 | 避免方法 | 检测方法 |
|---|-----|------|------|----------|----------|
| G.1 | 只测 happy path | demo 完美，生产翻车 | 测试集无对抗样本 | 测试集含边界/异常/注入/超长样本（E.1 联动） | 测试集覆盖率评估 |
| G.2 | 用 LLM 评 LLM 有偏 | 评分器偏爱自家模型 | 无校准 | 评分器先校准（人工标注对齐）；多评分器交叉 | 评分器-人工一致性 |
| G.3 | 测试集过拟合 | 测试集越调越高，真实更差 | 反复调参 | 保留 holdout 集+定期换新题 | 新旧题分数差 |
| G.4 | 无基线对比 | 改没改好说不清 | 无 baseline | 强制 baseline（上一版/开源 SOTA）对比（11-eval） | 对比报告必含基线 |
| G.5 | 忽略延迟成本 | 准确率 +5%，成本 +300% | 只盯准确率 | 评测含延迟/成本/失败率多维指标 | 多维指标看板 |
| G.6 | 人工复核缺失 | 错得离谱还上线 | 全自动流程 | 关键场景在线抽样人工复核（11-eval 在线层） | 复核覆盖率 |
| G.7 | 评测数据污染 | 测试题泄露进训练/提示词 | 无隔离 | 测试集隔离管理+防泄出 | 泄露检测（测试题命中率异常高） |

## J. 不要重复造轮子（现成方案清单，16 项）

> **原则**：第一优先找成熟方案（自己造轮子的成本 = 开发 + 维护 + 踩坑，通常 ≥5 倍）；只有当现成方案无法满足（私有化/合规/性能/深度定制）时才自研，且自研也要复用底层组件。

| # | 领域 | 现成方案（选型） | 解决什么 | 什么时候才自研 |
|---|------|------------------|----------|----------------|
| J.1 | 模型网关/统一接口 | OneAPI / OpenRouter / LiteLLM / BentoML | 多 provider 统一接入、密钥托管、限流、计费、模型热插拔（换 GPT 不用重写代码） | 需要深度定制路由策略/私有化计费时才自己写网关 |
| J.2 | Agent 编排 | LangGraph / OpenAI Agents SDK / Claude Agent SDK / AutoGen / ADK | ReAct 循环、子 Agent、状态机、HITL（本项目 07-workflow + AgentRuntime 已抽象，适配器模式） | 想全控制循环细节/深度定制调试体验时用 bare 自研 |
| J.3 | RAG 框架 | LlamaIndex / LangChain | 文档加载、分块、索引、检索、RAG 管线 | 只做 RAG 选 LlamaIndex；要全栈编排选 LangChain |
| J.4 | 向量数据库 | Milvus / Qdrant / pgvector / Chroma | 向量存储与检索（不要自己写向量检索） | 数据 <10 万条用 pgvector 即可；高并发才上 Milvus/Qdrant |
| J.5 | LLM 可观测性 | Langfuse / LangSmith / Helicone / OpenTelemetry | trace/评测/成本分析（本项目 12-monitor 对齐 OTel 标准） | 深度私有化时自研 trace 存储，协议仍按 OTel |
| J.6 | 任务队列 | Celery / RQ / RabbitMQ / Redis Stream | 异步任务、重试、调度（09-schedule 主循环可基于它） | 任务量小直接用 Redis+定时器，勿引入重型 MQ |
| J.7 | 认证授权 | Keycloak / Casdoor / Auth0 / 飞书·钉钉·企微 SSO | 登录、SSO、MFA、RBAC（16-C 全部现成） | 已有统一门户时对接它的协议，勿重写认证 |
| J.8 | 文档解析 | Unstructured / PyMuPDF / pdfplumber / docling | PDF/Word/PPT/Excel 文本抽取（16-D.2） | 特殊版式（复杂表格/合同扫描件）才加自研规则 |
| J.9 | OCR | PaddleOCR / Tesseract / 腾讯云·阿里云 OCR | 扫描件识别 | 中文识别优先 PaddleOCR，商用可选云 OCR |
| J.10 | 语音 | 现成 ASR/TTS API（腾讯/讯飞/OpenAI） | 语音转写与合成（08-voice） | 无需自研；离线才用 Whisper 等开源模型 |
| J.11 | 评测 | Ragas / Promptfoo / DeepEval | RAG 质量、LLM 应用回归评测（11-eval 可挂载） | 评测判分器可自研，但评测框架直接用现成 |
| J.12 | 部署推理 | vLLM / Triton / Docker / K8s / BentoML | 模型 serving、容器化、弹性伸缩 | 无 GPU 场景直接调 API，勿自建推理集群 |
| J.13 | 缓存 | Redis | 结果缓存、会话缓存、限流计数 | 直接用，勿自研 |
| J.14 | 搜索 | Elasticsearch / Meilisearch / OpenSearch | 全文检索、混合检索的 BM25 部分 | 数据量大才上 ES，中小规模 Meilisearch 更轻 |
| J.15 | 前端基础 | React+Vite / AntD / shadcn / Tailwind | UI 组件、流式渲染（本项目 admin 前端已基于此） | 无脑复用组件库，勿手写基础组件 |
| J.16 | 数据库 | PostgreSQL（+pgvector）/ SQLite | 业务数据存储（本项目资产模型全部关系型可落 PG） | 单体起步 SQLite/PG 均可，勿早期分库 |

> **自研前的灵魂三问**：①开源版/商业版真没有吗？（先搜）②现有方案哪里不满足？（列具体差距）③自研 5 年维护成本算过吗？（轮子要养）
